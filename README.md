## Python Apprenticeship
Dieses Repository dokumentiert meinen Einstieg in die Programmiersprache Python und begleitet meine Lernfortschritte im Rahmen des Python Apprenticeship.
Das Projekt besteht aus mehreren Lerntagen. An jedem Tag werden neue Python- und Git-Grundlagen erarbeitet und anschließend in einer praktischen Aufgabe umgesetzt.

## Lernziele 
Im Verlauf des Projekts lerne und übe ich unter anderem:
* Grundlagen der Programmiersprache Python
* Erstellen und Ausführen von Python-Programmen
* Arbeiten mit dem Terminal

* Arbeiten mit GitHub-Repositories
* Variablen und verschiedene Datentypen

* Dokumentation eines Projekts mit einer README-Datei

# Day 13 – Git Branches and Pull Requests

* Feature Branches erstellen und verwenden, um Änderungen unabhängig vom Hauptbranch zu entwickeln
* Pull Requests erstellen, um Änderungen zur Überprüfung und Zusammenführung vorzuschlagen
* Den Code-Review-Workflow anwenden, um Feedback zu erhalten und Verbesserungen umzusetzen
* Die Konzepte von Merge und Rebase verstehen und ihre Unterschiede kennenlernen
* Merge-Konflikte erkennen, analysieren und systematisch beheben
* Änderungen mit Git revert rückgängig machen, ohne die Commit-Historie zu überschreiben
* Git-Befehle zur Verwaltung von Branches, Commits und der Zusammenarbeit im Team anwenden

# Aufgabe

Ich erweitere meine Kenntnisse in Git und GitHub, indem ich eine simulierte Zusammenarbeit zwischen zwei Entwicklern durchführe. Dabei erstelle ich zwei Feature-Branches, nehme unterschiedliche Änderungen an derselben Datei vor und erzeuge dadurch einen Merge-Konflikt. Anschließend analysiere und behebe ich den Konflikt, indem ich die Änderungen manuell zusammenführe und das Ergebnis committe. Danach lade ich die Branches in ein GitHub-Repository hoch und erstelle einen Pull Request, um die Änderungen überprüfen zu lassen. Mithilfe eines simulierten Code-Reviews setze ich das erhaltene Feedback um und aktualisiere den bestehenden Pull Request. Abschließend lasse ich die Änderungen genehmigen, merge den Pull Request in den Hauptbranch und überprüfe den finalen Projektstatus. Während des gesamten Workflows dokumentiere ich die verwendeten Git-Befehle und beschreibe die Ergebnisse der einzelnen Schritte, um den Ablauf der Zusammenarbeit nachvollziehbar festzuhalten.

# Day 14 — GitHub Issues and Project Management

* GitHub Issues erstellen und verwenden, um Aufgaben, Fehler und Verbesserungsvorschläge zu dokumentieren und zu verwalten
* Issue Templates erstellen und verwenden, um eine einheitliche Struktur für neue Issues bereitzustellen
* Labels und Milestones nutzen, um Aufgaben zu kategorisieren, zu priorisieren und Projektziele zu organisieren
* Commits und Pull Requests mit Issues verknüpfen, um Änderungen nachvollziehbar zu dokumentieren und erledigte Aufgaben automatisch zu schließen
* GitHub Project Boards erstellen und verwenden, um Aufgaben zu organisieren und den Fortschritt eines Projekts zu verfolgen
* GitHub-Funktionen zur Aufgabenverwaltung und Zusammenarbeit im Team praktisch anwenden

# Aufgabe

Ich erweitere meine Kenntnisse in GitHub Issues und Projektmanagement, indem ich ein kleines GitHub-Projekt erstelle und dessen Aufgaben strukturiert verwalte. Dabei erstelle ich einen Milestone, lege mindestens fünf Issues mit passenden Beschreibungen an und versehe sie mit geeigneten Labels. Anschließend erstelle ich ein GitHub Project Board, füge die Issues hinzu und organisiere sie nach ihrem Bearbeitungsstatus. Für eine abgeschlossene Aufgabe nehme ich eine Änderung vor, erstelle einen Commit und einen Pull Request und verknüpfe diesen mit dem entsprechenden Issue. Nach dem Merge des Pull Requests überprüfe ich, ob das verknüpfte Issue korrekt geschlossen wurde. Während des gesamten Workflows dokumentiere ich die verwendeten GitHub-Funktionen und beschreibe die Ergebnisse der einzelnen Schritte, um die Aufgabenverwaltung und den Projektfortschritt nachvollziehbar festzuhalten.
